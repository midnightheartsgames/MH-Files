# MH Files — план реализации

Документ самодостаточный: его хватает, чтобы продолжить работу в новой сессии без истории.
Здесь — цель, архитектура, правила, которые нельзя нарушать, что уже сделано (0.1–0.5, 1.0-rc.1 и
доработки 0.2.x–1.0.x), чем этот план отличается от исходного черновика и почему, и что делать дальше.

---

## 1. Что строим

Файловый менеджер для Windows 10/11 на Rust. Не клон Проводника, File Pilot или OneCommander,
а своя программа:

* **скорость и управление File Pilot** — произвольные панели и вкладки, Инспектор, GoTo,
  палитра команд, пакетное переименование, мгновенный фильтр и поиск;
* **технические идеи OneCommander** — две панели, вкладки, переживающие перезапуск, быстрый
  предпросмотр, длинные пути, позже — колонки Миллера;
* **визуальный язык MH Monitoring и MH Sidebar** — та же палитра, Cuprum, карточки с тонкой
  рамкой, тумблеры, окно настроек с разделами слева.

Приоритеты (в порядке важности):

1. мгновенная навигация, UI никогда не ждёт диск, сеть, эскизы и расширения Shell;
2. всё доступно и мышью, и клавиатурой;
3. вкладки и несколько панелей;
4. быстрый предпросмотр;
5. хороший поиск;
6. родная интеграция с Windows Shell (корзина, буфер обмена, диалоги конфликтов, UAC);
7. один обычный `.exe`, без Electron/WebView, без фоновых служб для базовой работы.

## 2. Стек

| Слой | Что |
|---|---|
| UI | Rust 2024, `eframe`/`egui` 0.36, `glow` — как в MH Monitoring и MH Sidebar |
| Windows | крейт `windows` 0.62: Win32, COM, Shell — только в `crates/platform/src/win` |
| Модель | `serde`, `chrono`, `regex`, `uuid`, `nucleo-matcher` (нечёткий поиск) |
| Воркеры | `crossbeam-channel`, `parking_lot`, `image` (свой декодер), `encoding_rs` |
| UI-кэш | `lru` |

UI-фреймворк не меняем: перенос `theme.rs`/`widgets.rs` из MH Monitoring дал дизайн-систему
бесплатно, а сложные части файлового менеджера — Shell, буфер обмена, эскизы, наблюдение,
поиск — к GUI не относятся.

## 3. Что изменено относительно исходного черновика и почему

| Черновик | Сделано | Почему |
|---|---|---|
| Вкладки в заголовке окна (`Tabs ... − □ ×`) | В 0.3 — свой заголовок (значок, строка поиска по дискам, кнопки окна), вкладки остаются в каждой панели; отключается в настройках | Вкладки у каждой панели свои — в заголовок их не вынести без потери разбиений. Окно двигается и тянется за край средствами winit (`StartDrag`, `BeginResize`); тень даёт winit (`undecorated_shadow`), а Snap Layouts — подмена обработчика окна: над «Развернуть» `WM_NCHITTEST` отвечает `HTMAXBUTTON` (0.3.x, §6.6) |
| Индекс дисков в redb, первичное построение из MFT | Индекс — массивы в памяти (имена в нижнем регистре подряд, поиск подстрок `memchr`), снимок на диске — свой двоичный файл с контрольной суммой; построение — обходом каталогов, а у администратора на пустом индексе целого тома NTFS сначала имена из MFT (0.3.x) | Поиск по массивам — 9–32 мс на 2 млн имён без какой-либо БД; запись снимка 0,2 с, чтение до 1 с. MFT (`FSCTL_ENUM_USN_DATA`) даёт все имена за секунды, но без размеров и дат и только администратору — обход всё равно идёт следом и дописывает их; без прав он работает для любой ФС |
| Сортировщик — отдельная программа MH Sort | В 0.5 логика MH Sort перенесена в крейты MH Files (`core::sorting`, `fs::sorting`) вместе с тестами, окно — вкладка «Разложить» в стиле MH Files; `categories.json` и журналы — того же формата, категории при первом запуске берутся у установленного MH Sort | MH Sort — приложение, а не библиотека: подключить его как зависимость нельзя, а два разных окна для одной задачи — хуже, чем вкладка рядом с папкой. Поведение (правила пропуска, имена, журнал, отмена) сохранено один в один |
| Архивы как папки | Чтение: zip (deflate, deflate64) и 7z (LZMA/LZMA2, BZip2, Deflate, PPMd) крейтами `zip` и `sevenz-rust2` на чистом Rust, rar — внешней программой (7-Zip или `tar.exe` Windows 11); архив в архиве — через временную копию. Запись в zip — бросок файлов в «сжатую папку» Проводника (`IFileOperation`) | Свой код записи в архив — риск испортить файлы пользователя ради редкого сценария; C-библиотеки (zstd, bzip2-sys) усложнили бы сборку; распаковщик RAR несвободный — внешний процесс лицензию не затрагивает |
| Обработчики предпросмотра в дочернем окне | Отдельное всплывающее окно **без владельца** в своём STA-потоке, следует за главным окном по WinEvent | Дочернее окно или окно с владельцем из другого потока сцепляет очереди ввода: зависший обработчик (или `prevhost.exe`) заморозил бы и интерфейс |
| Обновление индекса по USN Journal | Пока программа открыта — рекурсивный `ReadDirectoryChangesW` на корень тома; после перезапуска — журнал USN, если программа запущена от администратора, иначе обход в фоне (с низким приоритетом диска) | Читать журнал USN без администратора нельзя, а требовать UAC при каждом запуске файлового менеджера — неприемлемо |
| Произвольные разбиения — в 0.2 | Дерево `LayoutNode` сразу, разбиения в любую сторону уже в 0.1 | Дерево не дороже жёстких двух панелей, а переделка `left/right` потом дорогая |
| Пакетное переименование — 0.2 | В 0.1 | Движок чистый и покрыт тестами; это «фирменный» инструмент |
| Рекурсивный поиск — 0.2 | В 0.1 (потоковый обход в ширину, отмена) | Обход — сто строк; индекс диска остаётся на 0.3 |
| Свои диалоги конфликтов и панель операций в 0.2 | В 0.1 копирование/перемещение/удаление идут через `IFileOperation` с **системным** прогрессом и диалогами конфликтов | Даёт сразу корзину, UAC, конфликты, отмену и «Отменить» в Проводнике. Своя панель операций — 0.2, через `IFileOperationProgressSink` |
| GoTo на Ctrl+L | GoTo — Ctrl+G и Ctrl+P; Ctrl+L и Alt+D — ввод пути | Ctrl+L/Alt+D в Проводнике и браузерах — адресная строка; ломать привычку незачем |
| Поиск V1 — нечёткий фильтр | Фильтр папки — слова в любом порядке или маска `*.png`, без нечёткости | В именах файлов нечёткое совпадение даёт мусор; нечёткий поиск — в палитре и GoTo |
| Выделение в `SelectionState` | Выделение хранится **путями**, плюс ленивый индекс путь→строка | Пересортировка, фильтр и правки наблюдателя не сбивают выделение; поиск строки — O(1) на 100 000 записей |
| «Generation-tagged results» | Один канал `Event` и `Ticket { owner, generation }` на каждый ответ | Конкретный механизм: UI выбрасывает ответы устаревших поколений |
| Установщик MSI (WiX) | Inno Setup: установка для текущего пользователя в `%LOCALAPPDATA%\Programs\MH Files` без прав администратора, плюс переносной zip | MSI для одного пользователя неудобен (ICE-ошибки, per-user-ограничения), WiX тянет .NET; Inno Setup — один `.iss`, ставится на GitHub Actions за секунды. Файловому менеджеру не нужны службы и HKLM: меню Проводника — в HKCU |
| Одна копия через мьютекс и `WM_COPYDATA` | Именованный канал `\\.\pipe\MH-Files-<хэш папки данных>-<пользователь>-<сеанс>`: первая копия — сервер, следующая отдаёт пути и выходит | Канал сам говорит, кто первый (`FILE_FLAG_FIRST_PIPE_INSTANCE`), не требует окна и HWND, и ответ «принято» приходит до выхода второй копии; переносная копия с другой папкой данных — другая программа. Вне Windows — Unix-сокет, чтобы проверять поведение в Xvfb |
| Только Windows | Под Linux собирается и запускается с упрощёнными заглушками | Тесты и проверка интерфейса (Xvfb, снимки) без Windows. Дистрибутив — только Windows |
| `parking_lot`, `lru` и т. д. «ориентировочно» | Используются там, где нужны: `parking_lot` — очередь эскизов, `lru` — кэш текстур | Лишних зависимостей нет |
| Масштаб шрифта отдельной настройкой | Масштаб всего интерфейса (`zoom_factor`), Ctrl+= / Ctrl+- / Ctrl+0 | Одна ручка вместо пяти, всё масштабируется согласованно |

## 4. Правила проекта (нарушать нельзя)

1. **В потоке UI нет ввода-вывода.** Ни `std::fs`, ни Shell, ни буфера обмена. Единственное
   исключение — то, что выполняется до создания окна: чтение настроек и сеанса, разбор
   командной строки, единственная копия, отметка о сбое, копия настроек при обновлении.
   Запись настроек — в фоне.
2. **Ответы воркеров помечены поколением** (`Ticket`). Ответ старого поколения никогда не
   затирает новое место (`Tab::current`).
3. **Списки виртуальные** (`ScrollArea::show_rows`): рисуются только видимые строки.
4. **Эскизы асинхронные и в ограниченном кэше** (LRU на 2048 значков и 400 эскизов).
5. **Все действия — через реестр команд** (`commands.rs`): кнопки, меню, палитра и хоткеи
   называют `CommandId`, выполняет его одно место (`actions.rs`).
6. **В UI нет Win32/COM.** Всё Windows-специфичное — `crates/platform/src/win`.
7. **Ничто не роняет UI**: недоступный путь, отключённый диск, битый файл, упавший обработчик
   эскизов — это `Err(String)` с понятным текстом в строке состояния.
8. **Ссылки и junction рекурсивно не обходятся** (поиск, подсчёт папок).
9. **Обычная семантика Windows**: корзина, конфликты, UAC — через `IFileOperation`.
10. **Разрушительная операция знает точный список путей** до выполнения; удаление насовсем
    показывает этот список и спрашивает всегда.
11. **Файлы настроек и сеанса версионные**, испорченный файл не теряется (`.broken`), запись —
    через временный файл и переименование.
12. **Возможности делаются вертикально**: модель + воркер + UI + тесты, а не россыпь трейтов.
13. Не начинать следующую фазу, пока предыдущая не работает **на Windows**, а не только
    компилируется. Фазы 0.2–1.0 сделаны заранее по просьбе владельца проекта; поэтому 1.0
    выходит выпусками-кандидатами (`1.0.0-rc.1`, `1.0.0-rc.2` — с доработками 1.0.x), а
    `1.0.0` — только после прохода §7 целиком.

### Потоки

```
поток UI (egui) ──задачи──► Workers ──► list / search / preview / complete     (поток на задачу)
      ▲                         └─────► images-0..2  (COM STA, очередь «последний первым»)
      │                         └─────► shell        (поток на действие, COM STA)
      │                         └─────► watch        (поток на папку + поток склейки)
            │                         └─────► drives       (поток на диск: уснувший HDD не мешает)
      │                         └─────► index-search (поток на запрос, внутри — по ядру на часть)
      │       Indexer ──────────────────► index-volume (поток на том, фоновый приоритет)
      └──────── Event + repaint ◄─┘
поток UI ──FileOp──► Executor ──► file-ops (один STA-поток, IFileOperation по очереди)
```

### Переход в папку

1. `Tab::navigate` меняет место, сбрасывает выделение, увеличивает поколение, отменяет старую
   загрузку, запускает новую и наблюдателя. Строка пути меняется в этом же кадре.
2. Воркер отдаёт пачки `Event::Listing` с `Ticket`. Вкладка принимает только своё поколение и
   досортировывает не чаще раза в 120 мс (на огромных папках — реже, по времени сортировки).
3. `ListingDone` — итог; ошибка показывается в списке.
4. Наблюдатель склеивает события 75 мс (не дольше 400 мс), перечитывает изменённые пути в фоне
   и присылает `Patch`: выделение и прокрутка остаются.
5. После своих операций вкладки с затронутыми папками перечитываются «мягко»: новый список
   копится отдельно и заменяет старый разом, без мигания.

- [x] **Проверка обновлений** по кнопке («О программе», команда «Проверить обновления»):
      один запрос к GitHub Releases через WinHTTP (системный прокси и сертификаты, без своих
      TLS-библиотек; вне Windows — `curl`). Пред-выпуски предлагаются, только если
      установлен пред-выпуск; «Открыть страницу выпуска». Модель — `core::update`
- [x] **Папки в MH Files по умолчанию** — галочка «Настройки › Система › Проводник»:
      `Directory\shell` и `Drive\shell` = `MHFiles` (двойной щелчок по папке на рабочем
      столе и в других программах). `Folder\shell` не трогается: на нём `Win+E`, «Панель
      управления», библиотеки. Убирается, только если там по-прежнему наше
- [x] **Архивы zip, 7z, rar** — ProgID `MHFiles.Archive` в `OpenWithProgids` (галочка в
      настройках и задача установщика): MH Files в «Открыть с помощью»; программой по

      командной строки открывается как папка
- [x] **Меню Windows с зависшим расширением**: сторож ждёт 6 с, затем меню бросается (уже
      не выскочит позже) и показывается меню без сторонних пунктов
      (`SHCreateDefaultContextMenu` без ключей реестра) с объяснением в строке состояния
- [x] **«Отменить» удаление в корзину**: `PostDeleteItem` сообщает путь объекта в
      `$Recycle.Bin`; отмена (`FileOp::Restore`) возвращает его на место через
      `IFileOperation` и убирает файл сведений `$I…`. Занятое имя — системный диалог
- [x] **Перетаскивание правой кнопкой**: внутри окна — меню «Копировать сюда / Переместить
      сюда / Создать ярлыки» (из архива — «Извлечь сюда»); наружу — OLE с правой кнопкой,
      меню показывает получатель (Проводник). Ярлыки — `IShellLinkW`
- [x] **Snap Layouts**: над своей кнопкой «Развернуть» окно отвечает `HTMAXBUTTON` (подмена

- [x] **Индекс из MFT**: пустой индекс целого тома NTFS у администратора сначала
      заполняется всеми именами за секунды (`FSCTL_ENUM_USN_DATA`,
      `VolumeIndex::from_records` — родитель всегда старше ребёнка, служебные записи NTFS и
      исключения отсекаются), обход следом дописывает размеры и даты
- [x] **Съёмные и сетевые диски в индексе** — две галочки в «Поиск по дискам»: подключённые
      диски подхватываются за 10 с, отключённые отпускаются (их снимок остаётся), остальные
      тома не перезапускаются
- [x] **Поиск по содержимому** (Ctrl+Alt+F): слова в тексте файлов папки и вложенных

- [x] **Архив в архиве**: путь через внешний архив (`a.zip\b.7z\x`), вложенный копируется

- [x] **rar** — через 7-Zip (`7z.exe` из Program Files) или `tar.exe` Windows 11: оглавление

- [x] **Запись в zip**: бросок файлов в открытый zip или на строку zip-файла — копирование

- [x] **Видео и звук в быстром просмотре**: Media Foundation Media Engine в своём потоке

      (`TransferVideoFrame` в текстуру D3D11) и приходит картинкой; Enter — пауза,

- [x] **Дубликаты**: порог размера и исключения (имя, маска, путь папки) — в шапке вкладки и
      в настройках; жёсткие ссылки на один файл копиями не считаются; «Жёсткие ссылки
      вместо копий…» с точным списком: копия заменяется, только если не менялась с поиска;
      ссылка создаётся рядом и встаёт на место переименованием
- [x] **Правила сортировки по дате и размеру** — поле `rules` в `categories.json` (MH Sort
      его пропускает): «старше N дней», «больше N МБ», только для своих категорий; файл идёт
      в `Папка\Категория`. Правка — в «Настройки › Сортировка»
- [x] **Сортировка по расписанию** — «Разложить › Параметры › По расписанию» (час, 6 часов,
      день, неделя) со снимком галочек; работает, пока программа открыта, пропущенное — при
      запуске; журнал и Ctrl+Z — как у обычной
- [x] **Файл на категорию**: строку плана можно бросить на категорию слева (пока тащат,
      видны и пустые категории) — меняется только звено категории (`Plan::reassign`)
- [x] **Пункты Проводника в своём контекстном меню** (как в OneCommander): под командами
      MH Files — 7-Zip, Git, PowerToys, «Отправить ▸», «Открыть с помощью ▸», «Создать ▸» со
      значками; в меню объектов, пустого места и боковой панели. Своё меню открывается

      заполняются заранее через `WM_INITMENUPOPUP`, пункты и картинки (`hbmpItem`, 32 бита,
      premultiplied) читаются из `HMENU` в дерево `ShellMenuItem`. Поток ждёт выбора, пока
      открыто своё меню, и выполняет команду тем же `IContextMenu`; закрыли меню —

      путь…), и повторы одной подписи убираются. Значки, которые расширение рисует само
      (`HBMMENU_CALLBACK`), и пункты `MFT_OWNERDRAW` не показываются — для них остаётся
      полное меню Windows (Shift+F10). Выключается в «Настройки › Файлы»
- [x] **Ctrl+колесо мыши** — масштаб, как Ctrl+Plus/Minus (щелчок колеса — шаг 10 %);
      буква диска перед названием («C: Локальный диск»); кнопка-шестерёнка настроек в строке

## 7. Проверка на Windows (обязательно перед 1.0)

Собрать: `cargo build --release` (MSVC). Пройти руками:

1. Запуск < 300 мс; диски появляются, уснувший HDD не задерживает остальные.
2. Папка с 100 000 файлов: прокрутка, End, Shift+стрелки, фильтр.
3. Сетевой путь `\\недоступный\ресурс` — ошибка в списке, окно отвечает, можно уйти.
4. Копирование большого файла: системный прогресс, отмена, конфликт имён, копия в ту же папку
   → «имя - копия».
5. Delete → корзина без вопроса; Shift+Delete → наш список и вопрос; слишком большой файл →
   системное предупреждение.
6. Ctrl+C в MH Files → вставка в Проводник и наоборот; Ctrl+X → вставка перемещает и чистит
   буфер.
7. Перетаскивание из Проводника в панель; между панелями с Ctrl/Shift.
8. Изменения папки извне (создать, переименовать, удалить в Проводнике) видны сразу,
   выделение не сбивается.
9. Эскизы jpg/png/mp4/pdf; значки exe/lnk свои; переход по папкам не ждёт эскизов.
10. Свойства одного и нескольких объектов; «Открыть с помощью»; терминал; Проводник.
11. Пакетное переименование `a↔b`; имя `CON`; столкновение с существующим файлом.
12. Перезапуск восстанавливает окно, панели, вкладки; окно на отключённом мониторе
    открывается на видимом.
13. Путь длиннее 260 символов: открыть, переименовать, удалить насовсем; в корзину —
    понятная ошибка.

    кириллицей, предпросмотр, извлечение; зашифрованный — понятная ошибка; без 7-Zip на
    Windows 10 — подсказка поставить 7-Zip.
66. Бросить файлы в открытый zip и на строку zip-файла — архив дописан, вкладка архива
    обновилась; конфликт имён — вопрос Windows.
67. Быстрый просмотр mp4 (H.264), mkv, mp3, flac: звук и картинка вместе, пауза Enter,
    Shift+стрелки, ползунки; HEVC без кодека — понятная ошибка; стрелки листают дальше и
    останавливают звук; закрытие просмотра — тишина.
68. Дубликаты: «от 1 МБ», исключение `node_modules` — поиск заново; «Жёсткие ссылки вместо
    копий» — свободное место выросло, файлы открываются; повторный поиск их не находит.
69. Правило «старше 365 дней — Архив» в «Настройки › Сортировка»: старые файлы — в
    `Архив\Категория`; MH Sort читает тот же `categories.json` без ошибок.
70. «По расписанию: каждый час» на папке «Загрузки» — через час (или при следующем запуске)
    файлы разложены, в строке состояния итог, Ctrl+Z возвращает; перетащить строку плана на
    другую категорию — «Куда» меняется.
71. Правый щелчок по файлу: своё меню сразу, ниже через доли секунды — пункты Windows со
    значками (7-Zip ▸, Git, PowerRename, «Отправить ▸» с дисками, «Открыть с помощью ▸»);
    «7-Zip › Добавить к архиву» открывает диалог 7-Zip; «Вырезать», «Удалить», «Свойства»
    не повторяются. С Shift — расширенные пункты. Пустое место папки: «Создать ▸» создаёт
    документ. Диск в боковой панели: «Форматировать», «Извлечь» у флешки. Меню закрыли
    без выбора — в диспетчере задач не копятся потоки. Выключить в настройках — снова
    пункт «Меню Windows».
72. Ctrl+колесо над списком, Инспектором и боковой панелью: масштаб меняется по шагу на
    щелчок, список при этом не прокручивается; щипок на тачпаде — плавно по шагам.

## 10. Пороги производительности

| Что | Цель | Как проверить |

| Запуск | < 300 мс до первого кадра | «Настройки → Система → Замеры», холодный старт; Linux (Xvfb, отладочная сборка) — 80–140 мс |

## 11. Сборка и проверка

```
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo check --workspace --target x86_64-pc-windows-gnu   # Windows-код с Linux
cargo build --release                                     # на Windows: MH-Files.exe
.\tools\build-release.ps1                                  # на Windows: exe, установщик, zip
```

`build-release.ps1` кладёт в `target\dist` установщик `MH-Files-<версия>-setup.exe` (если
стоит Inno Setup 6), переносной `MH-Files-<версия>-portable.zip` и exe с PDB. CI (job
`release`) делает то же и выкладывает артефактом.

Подпись: задать `MH_SIGN_PFX` (путь к `.pfx`) и `MH_SIGN_PASSWORD` или `MH_SIGN_THUMBPRINT`
(сертификат в хранилище, в том числе на токене); метка времени — `MH_SIGN_TIMESTAMP`
(по умолчанию DigiCert). Нужен `signtool` из Windows SDK. В CI — секреты репозитория
`MH_SIGN_PFX_BASE64` (`.pfx` в base64) и `MH_SIGN_PASSWORD`.

Выпуск: поднять `version` в `Cargo.toml`, написать `docs/releases/<версия>.md` и влить в
`main`. Job `publish` публикует GitHub Release `v<версия>` (тег — на этот коммит) с
установщиком, zip и `SHA256SUMS.txt`, если такого выпуска ещё нет; версия с `-` — пред-выпуск.

Под Linux программа запускается для проверки интерфейса (нужны `libxkbcommon-x11`, X11 или
Wayland). Настройки: `%APPDATA%\MH Files\settings.json` и `session.json`
(`~/.config/mh-files` вне Windows); в переносном режиме — `data` рядом с exe. Там же
`crashes` (отчёты о сбоях) и `backup\<версия>` (настройки до обновления). Снимки индекса: `%LOCALAPPDATA%\MH Files\index`
(`~/.cache/mh-files/index`); вне Windows по умолчанию индексируется домашняя папка.
